## 4. Le point `engine.ts:464` — erreur de diagnostic répandue

```ts
export function endTurn(state: BattleState): BattleState {
  const next = clone(state);
  if (next.phase === 'ended') return next;   // 462
  checkup(next);                             // 463
  if (next.phase === 'ended') return next;   // 464  ← TS2367
```

`checkup` (`engine.ts:429`) **mute** l'état et peut terminer la partie : `state.phase = 'ended'` en `engine.ts:363` et `engine.ts:378`.

- **Le test de la ligne 464 est nécessaire au runtime** : sans lui, un K.O. provoqué par un statut (Surcharge, Burn-out, Bloqué…) laisserait le tour continuer.
- **Le diagnostic correct** : TypeScript conserve le rétrécissement de type (`narrowing`) après `if (next.phase === 'ended') return next;`, et ne sait pas qu'un appel de fonction peut réaffecter la propriété.
- **Correction recommandée** : faire retourner l'état (ou un booléen) à `checkup`, par exemple `const after = checkup(next); if (after.phase === 'ended') return next;`.
- **Correction interdite** : supprimer la ligne 464. Un audit précédent le recommandait ; c'était un bug introduit, pas une simplification.

### 9.3 Ce que ça change pour la suite

- **Un audit gratuit doit être vérifié**, même quand il cite des commandes : la forme « commande + extrait » ne garantit pas que l'extrait est réel.
- Les mesures passant par un pipe (`npm run check | tail`) faussent le code de sortie : mesurer sans pipe, ou avec `PIPESTATUS`.
- Les modèles gratuits ne se valent pas : `nemotron-3.5` a exécuté 13 commandes sans erreur, `big-pickle` a répondu sans appeler un seul outil sur une autre tâche et a inventé un lien.
- Conséquence pour la carte wayfinder : la latence et la **fiabilité à appeler les outils** doivent être mesurées avant d'assigner un ticket à un modèle gratuit, pas après.
